# DevDock Ultra

Интерактивная инженерная энциклопедия на русском языке: шесть связанных доменов — **HTML, CSS, JavaScript, SQL, Git, Computer Science**. Это не набор уроков, а система: каждая тема — «документ» (20 разделов: определение, ментальная модель, примеры, типичные ошибки, упражнения, вопросы для собеседования, экзамен, проверка мастерства), а к модулям привязаны проекты с рубрикой оценки и самопроверкой.

Содержимое (проверяется валидатором): **180 тем, 42 проекта, 6 доменов, 56 «заметок дня»**.

| Домен | Тем | Проектов |
|-------|-----|----------|
| HTML | 41 | 7 |
| CSS | 43 | 7 |
| JavaScript | 26 | 7 |
| SQL | 27 | 7 |
| Git | 21 | 7 |
| Computer Science | 22 | 7 |

> **Для тех, кто продолжает работу (люди и ИИ):** прочитайте этот файл целиком, затем `DEVDOCK_PROGRESS.md` (журнал: что сделано и что дальше) и `AGENTS.md` (в этой версии Next.js есть ломающие изменения — перед кодом читайте `node_modules/next/dist/docs/`).

## 1. Быстрый старт

Нужен **Node.js 22** и npm.

```bash
npm install
npm run dev        # разработка
```

Откройте **http://localhost:3000**. Сайт работает целиком без регистрации, баз данных и ключей: прогресс хранится в браузере.

```bash
npm run build      # production-сборка (все 180 тем и 42 проекта генерируются статически)
npm run start      # запуск собранного сайта, http://localhost:3000
```

### Если что-то не работает (проверено на практике)

| Симптом | Причина и решение |
|---|---|
| Не работают поиск (Ctrl+K), переключатель темы, «Заметка дня» | Сайт открыт не по `localhost` (например `127.0.0.1` или адрес из VS Code). Dev-сервер Next 16 блокирует свои ресурсы для чужих origin. Для `127.0.0.1` и частных сетей это уже разрешено в `next.config.ts` (`allowedDevOrigins`); для другого хоста (туннель, проброс порта) добавьте его туда. `npm run build && npm run start` таких ограничений не имеет. |
| В консоли «A tree hydrated but some attributes… didn't match», в diff — `bis_skin_checked`, `bis_register` и т. п. | Расширение браузера (антивирус/«защита веб-страниц») дописывает атрибуты в HTML до гидратации. Это не ошибка сайта и не влияет на работу, только dev-предупреждение. Отключите расширение для localhost или откройте окно инкогнито. |
| Новые стили Tailwind «не применяются» в dev | Dev-сервер иногда держит устаревший CSS. Остановите его и запустите заново (`rm -rf .next/dev`, `npm run dev`). |
| `EADDRINUSE: 3000` | Порт занят: `npm run dev -- -p 3300`. |
| Сборка и dev делят папку `.next` | Не запускайте `next dev` и `next build` одновременно; перед сборкой остановите dev-сервер. |

## 2. Проверки качества

```bash
npm run typecheck          # TypeScript (tsc --noEmit)
npm run lint               # ESLint
npm run validate:content   # стандарт контента — главный страж качества (должно быть 0 ошибок)
```

`validate:content` не пропускает тему, если в ней меньше 900 слов, меньше трёх примеров кода, меньше двух упражнений, нет задачи-вызова, нет вопросов для собеседования трёх уровней, экзаменационных или закрепляющих вопросов, если у вопроса с вариантами пояснение короче 40 символов, если есть битая внутренняя ссылка или заглушка («скоро», `TODO`, lorem ipsum). Он же проверяет «заметки дня» (см. раздел 5). **Любые правки контента обязаны оставлять валидатор на 0 ошибок.**

Доступность и интерфейс проверялись в реальном Chromium (Playwright) + axe-core: **0 нарушений** на всех темах, проектах и разделах в ночном режиме и в режиме «бумага»; ширины 360–390 px без горизонтальной прокрутки; `prefers-reduced-motion` даёт статичную законченную картинку без бесконечных анимаций. После любых изменений интерфейса повторяйте эту проверку.

## 3. Что внутри для пользователя

- **Главная** `/` — «Карта знаний» (180 тем и 386 связей «опирается на», прогресс подсвечивает точки), «Продолжить с места», серия дней, очередь повторения, «Заметка дня» (цитаты, законы, проверяемые факты; английский текст + перевод).
- **Курсы** `/learn`, `/learn/<домен>`, `/learn/<домен>/<тема>` — страница домена с анимированным мотивом, ведомостью, модулями и отметками тем; тема — документ с оглавлением, прогрессом чтения и связями.
- **Практика, экзамен, собеседование** `/practice|exam|interview/<домен>` — упражнения и вопросы из тем с проверкой ответов.
- **Проекты** `/projects/<домен>/<проект>` — цель, сценарий, требования, подсказки, критерии приёмки, рубрика (сумма весов 100), эталон с самопроверкой `check.mjs`.
- **Поиск** — `Ctrl/Cmd + K`: темы, понятия, упражнения, вопросы, примеры кода, проекты (Fuse.js, индекс — `src/app/search-index.json/route.ts`).
- **Песочницы** `/playground` (HTML/CSS/JS в `iframe` без `allow-same-origin` + CSP, консоль) и `/playground/sql` (SQLite в браузере через sql.js, три учебных набора данных, 22 примера).
- **Карточки** `/flashcards` — интервальное повторение (SM-2-lite). **Моё** `/me` — прогресс, закладки, заметки, сниппеты, экспорт/импорт JSON.
- **Два режима чтения** — ночной «атлас» и светлая «бумага» (кнопка в шапке, выбор запоминается; код всегда на тёмных плашках).

## 4. Стек

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript 5.9 · Tailwind CSS v4 (токены через `@theme inline`) · Zustand (persist в localStorage) · Shiki (подсветка на сервере) · Fuse.js · sql.js · Framer Motion (минимально) · lucide-react.

Необязательный слой (включается переменными окружения, см. раздел 7): Clerk (вход), PostgreSQL через `pg` (хранение прогресса), роли admin / user / guest.

## 5. Устройство репозитория

```
src/

    learn|practice|exam|interview|projects/[domain]/…   layout.tsx задаёт data-domain (пигмент домена)
    api/ , admin/          серверный слой входа (раздел 7)
    search-index.json/     route handler: индекс поиска
  components/
    home/                  KnowledgeMap, Ledger («ведомость»), NoteOfDay
    motifs/DomainMotif.tsx шесть анимированных мотивов доменов
    layout/                SiteHeader, SiteFooter, DomainHeader, DomainSubnav, ThemeToggle, Logo
    content/               отрисовка тем: BlockView, TopicDocument, CodeView, AnnotatedCode, SqlRunner …
    nav/ practice/ playground/ flashcards/ me/ ui/ auth/
  content/                 КОНТЕНТ (TypeScript-данные)
    <домен>/domain.ts      модули, пигмент, ожидания; topics/*.ts; projects/*.ts
    dsl.ts  types.ts  sections.ts  registry.ts  nav.ts
    lore.ts                «заметки дня»
  lib/                     knowledge-graph.ts + graph-layout.ts (карта), highlight.ts (Shiki), search-index.ts,
                           sql-engine.ts, inline.tsx (мини-разметка), theme.ts, numerals.ts, auth/ …
  store/                   user-store.ts (весь прогресс ученика; ключ localStorage `devdock-user-v1`), hydrate.tsx, storage.ts
scripts/                   validate-content.ts, check-sources.ts, gen-sql-fixtures.mjs
docs/db/schema.sql         схема таблицы прогресса
DEVDOCK_PROGRESS.md        журнал работы и протокол продолжения
```

### Как устроены данные и страницы
- Контент — обычные TypeScript-объекты (`Domain → Module → Topic`, `Project`). `registry.ts` собирает их; страницы получают их при сборке (`generateStaticParams`), поэтому **все страницы контента статические**, серверного кода при чтении сайта нет.
- Состояние ученика — один Zustand-store (`user-store.ts`), гидратируется вручную (`StoreHydrator`, `skipHydration`), чтобы SSR и клиент не расходились. До гидратации компоненты показывают нейтральные значения (`useHydrated()`).
- «Карта знаний» вычисляется **на сервере** детерминированно (раскладка с зерном ГПСЧ, `lib/graph-layout.ts`), клиент только красит точки по прогрессу.
- «Заметка дня» выбирается по местной дате на клиенте; без JS показывается первая заметка.

### Как добавить контент
- **Тема** = один файл `src/content/<домен>/topics/<slug>.ts` + строка в `topics/index.ts` (порядок = порядок изучения; модуль задаёт поле `module`). Конструкторы блоков — `src/content/dsl.ts`; нумерация разделов 01–20 — `sections.ts`.
- **Проект** = файл в `projects/` + привязка `module.project` в `domain.ts`.
- В прозе работает мини-разметка: `` `код` ``, `**жирный**`, `*курсив*`, `[текст](url)`. В шаблонных строках с кодом нельзя `${` (TypeScript интерполирует), обратный слеш пишется `\\`.
- **Принцип достоверности:** числа, выводы команд и замеры получены реальным запуском (Node 22, CPython 3.11, gcc 13, PostgreSQL 16, git 2.43, Chromium), примеры кода запускались, у проектов есть самопроверка и набор «плохих» вариантов. Ссылки — только канонические (спецификации, MDN, RFC); внешние URL автоматически не проверяются.
- **«Заметка дня»** (`lore.ts`): `quote`/`law` требуют автора и источник, `fact` — источник, `folklore` — без выдуманной атрибуции, `attributed` — честная пометка «приписывается». Валидатор это проверяет. Не добавляйте цитаты «по памяти» без источника.

## 6. Дизайн-система «Атлас» (правила для новых экранов)

Файл токенов и анимаций — `src/app/globals.css`.

- **Палитра:** тёплая чёрная тушь (`--bg`), кость (`--fg`), шесть пигментов по доменам: vermilion (HTML), lapis (CSS), gamboge (JS), verdigris (SQL), madder (Git), tyrian (CS). Пигмент попадает в `--accent` / `--accent-text` / `--accent-ink` через `[data-domain="…"]` — **используйте `bg-accent`, `text-accent-text`, `border-accent`, а не конкретный цвет**, тогда страница сама окрасится в цвет домена. Страницы домена оборачивает `layout.tsx` с `data-domain`.
- **Режим «бумага»:** `[data-theme="paper"]` на `<html>` переопределяет токены (пигменты темнеют до контраста AA). Выбор хранится в `localStorage["devdock-theme"]`, применяется inline-скриптом в `<head>` без мигания. Плашки кода (`.bg-code`) остаются тёмными и внутри себя возвращают ночные токены — не задавайте им цвета жёстко.
- **Типографика:** заголовки — `font-display` (Spectral, лёгкие, отрицательный `tracking`), текст — `font-serif`, интерфейс — `font-ui`, подписи — `.label` / `.eyebrow` (Martian Mono, капсом). Углы почти квадратные (`rounded-[3px]`), без градиентов, свечения и «стекла»; разделители — волосяные линии (`border-line`, `border-line-strong`).
- **Анимация должна что-то сообщать:** рост дерева разбора, сигналы по связям «опирается на», цикл событий, отметка «изучено». Все анимации имеют статичный вариант в `@media (prefers-reduced-motion: reduce)`. Анимации SVG-мотивов — чистый CSS (классы `m-*`), у карты — `km-*`.
- **Контраст и a11y:** любой новый цвет текста проверяйте axe-core в обоих режимах. Не используйте `text-white`/`bg-black` и хекс-цвета в компонентах — только токены.

## 7. Регистрация, роли и база данных (необязательный слой)

По умолчанию сайт работает **без** этого слоя (гость, прогресс в браузере). Слой включается, когда заданы переменные окружения; без них код входа не подключается и ничего не меняется.

Роли:
- **guest** — не вошёл; прогресс только в этом браузере;
- **user** — вошёл через Clerk; прогресс синхронизируется с PostgreSQL и доступен с любого устройства;
- **admin** — e-mail входит в `ADMIN_EMAILS` или в Clerk у пользователя `publicMetadata.role = "admin"`; открывает `/admin` (список пользователей и их прогресс).

Переменные окружения (образец — `.env.example`; файлы `.env*` в git не попадают, кроме образца):

| Переменная | Для чего |
|---|---|
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | публичный ключ Clerk (`pk_…`) |
| `CLERK_SECRET_KEY` | **секретный** ключ Clerk (`sk_…`) — только в окружении хостинга/`.env.local`, никогда в git и чатах |
| `DATABASE_URL` | строка подключения PostgreSQL (Neon, Supabase, Vercel Postgres…) |
| `ADMIN_EMAILS` | e-mail администраторов через запятую |

Слой включается, если заданы **оба** ключа Clerk. Без `DATABASE_URL` вход работает, а синхронизация и `/admin` отвечают «база не настроена».

Как это работает:
1. `src/proxy.ts` (в Next 16 бывший `middleware`) подключает Clerk; `layout.tsx` оборачивает приложение в `ClerkProvider` (русская локализация) только при включённом слое.
2. `GET/PUT /api/state` хранит JSON-состояние ученика (то же, что экспортирует `/me`) в таблице `user_state` (схема — `docs/db/schema.sql`, создаётся автоматически при первом запросе).
3. `CloudSync` при входе сравнивает время изменения локального и серверного состояния: если на сервере новее — применяет через `importState`; иначе отправляет локальное; дальше отправляет изменения с задержкой 2,5 с. Политика — «последняя запись побеждает».
4. `/admin` — серверная страница: проверка роли на сервере, список пользователей из Clerk + прогресс из БД.

Настройка с нуля: создайте приложение в Clerk (dashboard.clerk.com) → скопируйте ключи; создайте бесплатную базу PostgreSQL (например Neon) → скопируйте `DATABASE_URL`; заполните переменные локально в `.env.local` и на хостинге. В Clerk добавьте домен продакшена в разрешённые.

## 8. Деплой (Vercel — самый простой путь)

1. Запушьте репозиторий на GitHub.
2. На vercel.com: **Add New → Project → Import** репозитория. Framework — Next.js (определится сам), Node.js — 22.x, команды по умолчанию (`npm run build`).
3. Для «чистого» сайта без входа переменные не нужны — деплой работает сразу.
4. Для входа и синхронизации добавьте в **Settings → Environment Variables** четыре переменные из раздела 7 и передеплойте. В Clerk добавьте адрес `*.vercel.app` / ваш домен.
5. Первый запрос к `/api/state` сам создаст таблицу.

Другие хостинги: любой Node-хостинг — `npm ci && npm run build && npm run start` (порт — переменная `PORT`). Статическая выгрузка (`output: "export"`) **не подходит** при включённом слое входа (нужны API-маршруты).

Перед деплоем: `npm run typecheck && npm run lint && npm run validate:content && npm run build`.

## 9. Известные ограничения и что дальше

- Внешние URL источников не проверяются автоматически (в среде разработки закрытый прокси).
- Не запускались Lighthouse и «тест нового ученика» (прохождение пути от первой темы до итогового проекта человеком) — см. `DEVDOCK_PROGRESS.md`.
- Поиск не знает транслитерации («флексбокс» ↔ Flexbox): можно добавить синонимы в индекс.
- Слой входа проверен на уровне типов, сборки, API без сессии и работы с БД; **живой вход через Clerk нужно проверить на вашем ключе** после деплоя.
